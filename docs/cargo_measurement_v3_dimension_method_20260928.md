## 2. 从输入到输出的完整链路

```text
左右 IR 原图（1280×800，按设备时间戳配对）
    ↓ 标准 FoundationStereo，原生分辨率，32 次迭代
视差 disparity_pixels.npy（单位：原图像素）
    ↓ 左右 IR 内参 + 95.2326965 mm 基线
光轴深度 depth_m_provisional.npy（单位：米）
    ↓ 针孔反投影
每个有效像素对应的三维点 XYZ（单位：米）
    ↓ 人工顶面内部 ROI、货物外轮廓 ROI、承载板 ROI
鲁棒拟合货物顶面与承载板平面
    ↓ 顶面残差 <10 mm，保留最大连通区域
支持像素的射线与拟合顶面相交
    ↓ 顶面二维坐标中的最小面积包围矩形
长、宽 + 矩形四角至承载板的平均法向距离
    ↓ 米 ×1000，写入 JSON/CSV，显示时保留一位小数
报告长 × 宽 × 高（mm）
```

本链路未使用 YOLO 检测或分割，也未执行 RGB 配准。PLY 是供查看的输出，并非先从点云软件人工量出尺寸再填入报告。

## 4. 视差如何变成米制深度

包内 `calibration.json` 给出的左 IR 内参及左右基线为：

| 参数 | 数值 | 含义 |
|---|---:|---|
| fx、fy | 620.138794 px | 原生图像焦距 |
| cx | 637.5 px | 左图主点横坐标 |
| cy | 406.0 px | 左图主点纵坐标 |
| 右图 cx | 637.5 px | 用于主点差修正 |
| B | 95.2326965 mm = 0.0952326965 m | 左右 IR 基线长度 |
| 图像宽、高 | 1280、800 px | 标定对应网格 |

对左图像素 `(u,v)`，视差记作 `d(u,v)`，计算为：

```text
Z = fx × B / [d − (cx_left − cx_right)]
```

本次左右主点相同，因此实际简化为：

```text
Z_m = 59.05748955687802 / d_px
```

例如仅作公式演示，视差30 px对应约1.968583 m的光轴深度；这不是指定测量点的实测值。程序先要求视差有限且大于0，右图对应横坐标 `u−d` 位于 `[0,1279]`，再进行换算。无效位置保留为NaN。

`depth_m_provisional.npy` 已经是米，不再乘标定 JSON 中的 `depth_unit_mm`；后者属于设备原始深度编码参数。本测量直接使用网络视差与基线，没有拿设备 Raw 深度值再次缩放。

## 5. 深度如何变成三维点

每个像素按左 IR 内参反投影：

```text
X = (u − cx) × Z / fx
Y = (v − cy) × Z / fy
P = [X, Y, Z]
```

坐标原点为左 IR 相机光心，X向右、Y向下、Z向前，单位均为米。Z是光轴深度，并非点到光心的欧氏距离。此时得到的是相机坐标，还没有变成地面或世界坐标。

测量脚本在内存中构造全图XYZ。v3包保存了原生深度、最终矩形四角XYZ及局部PLY，未提供全场景逐像素XYZ文件。

## 6. 哪些部分是人工选择的

`annotations.json` 保存三类人工区域，均在原始左 IR 图像上选取：

- `corners`：顶面内部拟合区域；默认采用17×17全1核腐蚀，即参数 `erosion=8`，减少边缘坍塌点对平面的影响。人工四角本身不作为最终长宽边界。
- `silhouettes`：货物外轮廓排除区域，防止周围板面或设备进入顶面支持区域；它仍会约束最终可用的边界范围。
- `board`：可见白色承载板区域，用于拟合高度参考平面；本轮没有另做地面标定。

例如第33组的原图像素坐标为：

```text
顶面内部区域：[(702,474), (865,450), (875,519), (708,537)]
货物外轮廓：  [(691,463), (867,444), (881,520), (706,541)]
承载板区域：  [(625,290), (1035,290), (1035,420), (625,420)]
```

本次属于半自动测量。人工区域来自当时助手对原图的目视选取，不是训练标注或经过独立人工精度验收的标准边界。

## 7. 顶面与承载板如何拟合

对两个区域分别保留有限三维点，执行鲁棒SVD平面拟合，平面形式为：

```text
n · P + b = 0，且 ||n|| = 1
```

先求点集中心，再对中心化点集做SVD，取最小奇异值对应方向为单位法向量；统一使法向量Z分量非正。随后计算残差，并以残差中位数为中心、MAD为尺度剔除异常点，最多迭代8次：

```text
m = median(当前内点残差)
MAD = median(|当前内点残差 − m|)
保留条件：|残差 − m| < max(0.001 m, 4 × 1.4826 × MAD)
```

拟合至少需要100个有效样本。原生测量使用 `sample_step=1`。第33组顶面拟合7411点，板面最终内点53833个；平面内点RMS分别约0.244 mm和0.309 mm。这些数字描述点云对平面的贴合程度，不等于物体尺寸的真实误差。

## 8. 长、宽如何计算

最终长宽由 `top_rectangle()` 产生，具体步骤为：

1. 对货物外轮廓内的有效三维点计算到拟合顶面的距离，保留 `|n_top·P+b_top| < 0.010 m` 的点。四组都使用10 mm阈值。
2. 对保留像素取最大连通区域，形成 `top_support_mask.png`。第33组保留12722个支持像素。
3. 对每个支持像素构造射线 `r=[(u−cx)/fx,(v−cy)/fy,1]`，求射线与拟合顶面的交点：`P_plane = −b_top/(n_top·r) × r`。因此边界点的平面坐标由像素位置及拟合顶面共同确定，不直接使用噪声较大的边缘原深度。
4. 在顶面建立正交二维坐标系，把交点转换到该平面坐标。
5. 使用 OpenCV `minAreaRect` 求最小面积包围矩形，较长边记为 `length_mm`，较短边记为 `width_mm`，从米乘1000转为毫米。

这不是二维图像框的宽高乘一个固定比例，也不是三维X/Y轴方向的极值相减。矩形位于拟合顶面上，可以随箱体在图像中的旋转而转动。

此方法用顶面内部的平面约束缓解边缘深度坍塌，但没有重建不可见的背面。最终矩形仍会受人工外轮廓、阈值、支持点缺失或离群点影响。

## 9. 高度如何计算

将最终矩形四角恢复为三维点 `C1…C4`，按承载板平面计算：

```text
H_mm = 1000 × mean(n_board · Ci + b_board), i=1…4
```

板面法向量为单位向量，因此该表达式给出有符号法向距离。四角均值等价于矩形中心到板面的距离；当前场景中货物顶面在板面朝向相机的一侧，结果为正值。

报告中的高对应字段 `height_above_board_mm`。它不是相机Z坐标差，不是货物最大点减最小点，也不是已标定的离地高度。仅在箱体底部接触板面且姿态符合假设时，可把它解释为箱体高度；顶面倾斜或箱体悬空时需另行解释。

## 12. 尺寸如何写入报告和文件

测量脚本先执行 `measure()` 得到平面与人工四角诊断，再执行 `top_rectangle()`。随后用 `result.update(automatic)` 将最终支持区域矩形的长、宽、高和四角XYZ写入主结果；人工四角估计另外存入 `manual_corner_diagnostic`。

| 文件或字段 | 内容与单位 |
|---|---|
| 每组 `measurement.json` | 最终长宽高、平面、敏感性、来源哈希及状态；尺寸字段单位mm |
| 汇总 `measurements.json` | 四组完整结构化结果 |
| `measurements.csv` | 帧号、DOE、类型、三项尺寸及 `physical_accuracy_verified=False` |
| `measurement_overlay.jpg` | 原左IR上的矩形、角点、选区及保留一位小数的尺寸 |
| `top_support_mask.png` | 最终10 mm阈值下的支持像素 |
| `top_corners_xyz_m.npy` | 最终矩形四角三维坐标，单位米 |
| `depth_m_provisional.npy` | 800×1280 float32深度，单位米，无效为NaN |
| `disparity_pixels.npy` | 原生视差，单位像素 |
| `top_and_reference_board.ply` | 货物外轮廓ROI与板面ROI中的原始反投影点，单位米，IR灰度颜色 |
| `height_0_to_350mm.png` | 相对板面高度伪彩色，显示范围0～350 mm |
| `edge_profile.png` | 局部5行高度中位数剖面及旧半分辨率对照 |
| `START_HERE.html`、`README.md` | 面向阅读的标记图、结果表、方法及限制说明 |

PLY保存的是相应区域的原深度反投影点，未把所有点压平到拟合顶面；尺寸计算中射线与平面的交点另行计算。伪彩色与JPEG标记图只供观察，不用来读取米制数值。

包内 `opposite_edges_mm`、`direct_corner_depth_dimensions_mm` 等诊断字段源自人工四角或角点3×3深度采样，不能覆盖主结果。v1曾因人工四角内缩得到第33组约509.6×203.8 mm；最终v3已改用支持区域矩形，过程值仅用于审计。

报告构建脚本读取测量结果来组织页面和说明；现有HTML摘要还有固定的一位小数文本。复核应以包内最终JSON为依据，改测量数据后不能只沿用旧页面数字。
